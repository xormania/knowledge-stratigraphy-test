# Support and discussion

Start with [README](README.md), [TESTING](TESTING.md), [PROTOCOL](PROTOCOL.md), and
[CONTRIBUTING](CONTRIBUTING.md). Use the issue chooser for reproducible bugs, proposals,
probe evidence, and focused questions. Search existing issues before opening another.

For a harness problem, provide the framework commit, OS/Python, harness version,
requested model and observed model separately, exact sanitized command, expected/actual
behavior, and a minimal log excerpt. Do not upload full account histories or credentials.

Thoughtful questions and counterexamples are welcome. Broad redesigns should begin as
proposals, not surprise rewrites. The project has no separate chat server or guaranteed
support schedule. GitHub Discussions may be enabled later without changing the proof
requirements for code contributions.

Security issues use [SECURITY.md](SECURITY.md), not ordinary public support.
